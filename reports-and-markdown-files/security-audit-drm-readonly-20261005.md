## Findings requiring a separately authorized DRM task

**HIGH — F01: failed Packager command discloses content-key arguments.** `apps/worker/src/services/video-processing/packaging.service.ts:39` passes the raw content key in `--keys`; `apps/worker/src/processors/video.processor.ts:133` logs the raw exception message, writes it through `updateJobStatus`, and rethrows it into BullMQ failure handling. Node execFile failure messages include command arguments. The audit Docker proof uses a fixed synthetic placeholder, prints only a boolean/assertion, and makes no media/production mutation. A log/job-data reader may obtain the failed attempt's content key and decrypt any corresponding retained partial artifacts. This does **not** establish disclosure of successfully published video keys or an authenticated student route to those records. Recommended bounded repair: replace subprocess errors at the packaging boundary with an allowlisted category; never retain raw command/stderr/key-bearing messages in logs, PostgreSQL or queue failure data; preserve useful exit code/category/request identifiers. Add failure/timeout tests that inspect all three sinks, and assess prior logs/job data privately for exposure/rotation of affected keys. No code change here because root AGENTS.md restricts nested maintenance. CWE-532 / CWE-312; OWASP2025 A09 logging and A04 cryptographic failures.

**MEDIUM — F03: webhook address predicate misses mapped IPv4 and fetch resolves DNS again.** `apps/api/src/services/webhook.service.ts:29` only recognizes selected dotted mapped-address strings, whereas Node URL canonicalization converts mapped loopback into hexadecimal IPv6. The network-disabled Docker proof runs the actual copied pure predicate and confirms its false-negative. `assertSafeWebhookUrl` resolves first; `deliverWebhook` later fetches the hostname independently, permitting DNS check/use divergence. Application credential holder controls its registered destination. HTTPS/443, certificate verification and blocked redirects constrain practical impact; the proof did not access any private server. Repair proposal: normalize IPs with a vetted parser, reject all nonpublic/reserved mapped ranges, pin validated DNS results in the actual connection (including TLS SNI), and enforce independent egress policy. Test public/private IPv4/IPv6/mapped/alternate forms, rebind and redirects in a disposable fixture. CWE-918; API2023 SSRF. No nested code change.

**HIGH component advisory — F02:** pnpm audit reports one development `braces`3.0.3 finding through ESLint/globby. Not a proven public DRM runtime exploit. Registry latest remained3.0.3; pnpm suggested >=3.0.4 while the published advisory listed no fix, so that metadata is not an installable verified remediation.

## Controls traced

Applications creation requires separate administrative bearer with timing-safe digest comparison; application secrets Argon2 checked; platform assertions require asymmetric allowlist/issuer/audience/claims/app binding and durable jti replay check. Playback authorization binds active unexpired record to tokenId/application/asset/user/device. Media/status/deletion/device/audit/webhook paths scope queries by authenticated application. Gateway objects derive an owned media prefix, reject dot traversal, validate ranges, stream privately and no-store. Outgoing webhook secrets AES-GCM encrypted, HMAC signed, HTTPS443 and redirects blocked. Worker commands use execFile argument arrays, random temporary folders and fixed source names, size/duration/dimension/time bounds. This source evidence is not a blanket approval of all DRM internals; native processor CVEs, tenant regression matrix, real licenses and deployment permissions remain manual.
