# Course photos and 10-second player controls — 2026-10-08

Owner requested representative course images on the landing page, approved adding a cover field, then clarified that the course editor should upload a photo. Owner also supplied the rewind/forward “10” control reference. Implemented on the requested existing `dev` branch; pending earlier footer and landing-page edits are preserved. No commit/push, production deployment or external DRM changes.

## Behavior

- New course creation through the admin UI requires a photo; editing existing courses allows adding/replacing it. JPEG/PNG/WebP source files up to 10 MiB are decoded, resized to at most 1200px and re-encoded as a JPEG up to 128 KiB. The editor previews the selected photo, reports invalid images and waits for processing before saving. Upload is submitted atomically with course details, using existing admin authentication, Origin and CSRF guards. The JSON API retains backward compatibility for old clients and pre-existing courses without covers.
- Platform PostgreSQL stores small image objects in the new `CourseCover` table with MIME/size database constraints and nullable `Course.coverId`. Browser and server checks bound size, file type, signature and dimensions. No browser-supplied external URL is fetched. This follows the existing small-image database storage precedent used for payment QR images and adds no storage deployment dependency. Revision drafts inherit the selected cover, replacement affects only the draft, and publication adopts the new selection. Image rows remain available to referenced historical revisions; no historical data cleanup is introduced.
- Public API metadata contains a versioned cover path, with bytes served separately only while the course is published and not pending deletion. Draft image requests require ADMIN. Historical cover routes are hidden. Public responses revalidate visibility; admin responses are private/no-store. Landing/catalog cards and offer pages render the cover with localized alternative text and a stable 16:9 area. Missing/broken covers show the existing-brand fallback; actual local courses were not assigned invented images.
- Rewind and Forward sit beside Play with circular-arrow icons and “10”. Arabic/English tooltips and labels describe the action. Seeking uses the current media position, clamps to zero/duration and is disabled without a finite duration or when the player is expired/in error. Existing seeking events handle tracking and progress. Chronological directions remain fixed in Arabic. Compact player layouts retain 44px buttons, move time to a second row and hide the volume slider while retaining Mute.
