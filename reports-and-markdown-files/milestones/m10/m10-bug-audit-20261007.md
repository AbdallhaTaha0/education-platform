## Confirmed findings

### F1 — P2: final playback interval is discarded

`client/src/features/learning/player/viewTracking.ts:83` clears its anchor immediately for paused/ended samples. `Player.tsx:399` observes the ended state before flushing. With continuous playing samples from 0 through 29,750ms every 250ms and natural end at 30,000ms, actual clock reports 29,750ms, below the required 30,000ms threshold. A complete 30-second video can therefore finish without any count. Pause/end boundaries also undercount their final inter-sample interval. Reproduced using the actual elapsed-clock module in a Docker runner. Earlier 30.25-second browser proof does not cover this exact boundary. Fix direction: credit the bounded final interval known to have been playing before ending/resetting; preserve exclusion of pause/seek/buffer gaps and stale samples.

### F2 — P2: same-student selection retains stale guardian availability

`AdminCourseStudentsPanel.tsx:35` keeps the old selection object whenever student ID is unchanged. Roster fetches new contact availability, but clicking the same student does not update the report workspace. Reproduction in real Chromium with current compiled client and labeled synthetic API: select a student without contact; update synthetic roster contact availability; trigger search/refetch; roster now says contact available; click same student; Send remains disabled. Selecting another student and returning restores Send. Reverse change can leave an enabled action until the API rejects it; current backend/contact checks still prevent wrong-recipient navigation. Fix direction: update selected name/contact metadata from the current row even when identity is unchanged, without unnecessarily resetting the report.

### F3 — P2: oversized-report recovery cannot open the chat after copying

`useParentReportHandoff.ts:58` builds the complete text URL before checking the manual channel. Oversized text correctly yields PART_TOO_LONG and stays available for copying. After copying, “Open WhatsApp” calls the same builder with the same oversized text, fails again and never navigates. Docker reproduction over actual hook: 6,000 Arabic characters; copy succeeds, manual open still PART_TOO_LONG, no location assignment. Compact UI does not expose the complete registered recipient, so its offered recovery flow cannot finish opening the intended chat. Fix direction: after explicit copy, offer a freshly contact-checked chat-only URL for pasting the complete message, preserve text until handoff/cancel, and avoid marking copy alone as opened/sent.
