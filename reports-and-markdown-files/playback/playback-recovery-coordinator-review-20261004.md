## Required corrections

| Priority | Finding | Concrete evidence and required behavior |
| --- | --- | --- |
| P1 | Audit failure has no durable reconciliation | `server/src/modules/learning/devices/service.ts` returns `auditPending:true` from its catch, but persists no retry/intent. A retry with `released:false` immediately returns `auditPending:false`. The assigned prompt explicitly requires an established durable mechanism for this partial outcome. Persist recoverable, sanitized operation state and reconcile the platform audit across outages/restarts/ambiguous external outcomes; do not imply a failed write rolled back a successful external release. The synthetic service probe reproduced the loss. |
| P1 | NOOP is falsely treated as confirmed recovery | `OwnSessionRecovery.tsx`'s final closure branch sets `outcome='ended'` and invokes `onRecovered`. The existing server end service returns NOOP for missing, foreign or otherwise ineligible references; it is not confirmation that the external stream slot was freed. The actual component reproduction invokes the callback after NOOP. Only CONFIRMED may offer/trigger restart. QUEUED and NOOP need distinct truthful feedback and reconciliation. Revalidate/reset stale selection when lists change. |
| P1 | Hiding a tab terminates playback without a page exit | `CourseLearningPage.tsx:111` registers an anonymous visibility listener and calls `endRef.current` whenever the document becomes hidden. `usePlayback.end` clears the current grant and credentials immediately, so ordinary switching tabs/apps ends playback. The approved assignment permits best-effort current-player page-exit/navigation cleanup, while background/offline abandonment policy remains a proposal. Remove this background-tab termination; retain pagehide/unmount behavior and clean up every registered listener. The anonymous listener is currently never removed on unmount. This finding is established from the event handler and end implementation; no background timeout policy is inferred. |
| P2 | The bounded session list can omit the session blocking recovery | `sessions/service.ts:38` includes ACTIVE and all ENDED rows, sorts solely by newest creation and takes ten. Ten newer completed sessions can hide an older ACTIVE or pending-termination session that still consumes the stream slot. Prioritize recoverable references within the same authenticated scope and bounded result, retaining honest lifecycle state; test the older blocker with more than ten newer completed rows. This is a source/query finding, not a reproduced PostgreSQL scenario. |
| P2 | Unsupported media is classified as a gesture problem | `Player.tsx:345` handles NotSupportedError inside the gesture branch, dispatching PLAYBACK_GESTURE_REQUIRED. Its later UNSUPPORTED_PROVIDER ternary can never see that error. The user receives the wrong next action. Separate NotAllowedError (gesture, preserve grant) from NotSupportedError (supported-media/browser guidance) and guard stale play promises after teardown/switch. The two new player tests exercise only the label helper, not the actual play rejection path. |
| P2 | Ambiguous device release leaves stale UI available for resubmission | `AdminStudentDevices.tsx` refreshes inspection only in the success path. A timeout/network error may follow an external release, but the catch labels it unavailable and the finally immediately enables stale release controls. Refresh/reconcile uncertain outcomes before presenting a definitive result or permitting a resubmit, as required by the assigned prompt. Preserve active/refused and revoked/banned protection. |
| P1 | Harness cleanup logs an inspection it does not perform | `docker/playback-recovery-review/run.mjs`'s finally prints “Verifying labels/mounts” and immediately issues both `compose down -v` calls. There is no resolved-container/mount/volume ownership guard before removal. The owner's mandatory prompt rule requires actual inspection, not a log message. Add fail-closed guards and verify command failures before claiming zero resources. The coordinator did not run this whole harness unchanged. |
| P2 | Browser evidence does not establish the claimed player/recovery behavior | The worker browser flow accepts `toggleCount <= 1` (zero passes) and accepts `no-frame-yet` for containment. Its student flow loads the learning page without submitting recovery or starting a grant. These checks do not establish a present single control, watermark/caption containment, play rejection, fullscreen, advancing time, or correct CONFIRMED/QUEUED/NOOP transitions. Replace permissive checks with actual stateful browser assertions. Keep harness-only mocks explicitly labelled and real-provider claims separate. |
