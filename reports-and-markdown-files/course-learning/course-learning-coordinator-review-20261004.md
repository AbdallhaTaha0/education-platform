## Frontend findings to cover during combined review

- `materials/api.ts` uses auth `apiFetch`, which throws auth `ApiError`, for JSON reads/deletes. Callers recognize only `LearningApiError`, so safe error categories are discarded as UNKNOWN; materials authorization errors cannot trigger the intended access-loss cleanup. Normalize errors at the materials API boundary and cover actual denial responses.
- `useLessonMaterials` does not clear/tag the previous lesson's materials at the start of a lesson change. Until the next response arrives, a new lesson can show the old lesson's resources and caption availability; selecting captions may fetch an old ID. Bind rendered state and asynchronous results to the selected lesson. Include Off/language-change cancellation/loading-state regressions and loss of publication/access, not only expiry.
- `isValidWebVtt` rejects common CRLF header lines because header suffix contains `\r`. Verify bytes accepted by the server with both LF/CRLF, Arabic text and actual cues; client plausibility checks should not reject valid server-validated files.

These are coordinator source-review findings; no worker implementation files were edited. The 33 frontend browser checks use explicit materials/player mocks and cannot establish these real transport/error/lifecycle behaviors.
